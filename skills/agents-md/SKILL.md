# Update Agent Conventions

## Workflow

1. Identify a verified lesson from implementation, security review, or closeout and the project behavior it should change.
2. Check the existing `AGENTS.md` for overlap or conflict. State the proposed rule in actionable, scoped terms.
3. Edit only the relevant convention after the work authorizes that project change, and validate the resulting instructions.
4. Record the rule's source evidence and any follow-up evaluation needed.

## Boundaries

- Do not copy private paths, credentials, logs, or transient task details into durable project memory.
- Do not claim a model or workflow behavior was tested when it was only proposed.

## Output Contract

Report the convention added or revised, its evidence, affected scope, validation, and unresolved questions. Write user-facing content in the user's language.
